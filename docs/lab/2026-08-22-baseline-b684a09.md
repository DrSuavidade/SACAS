## Experiment policy from here

1. One hypothesis per commit (e.g., "raise goal-rank cutoff floor to 5").
   No unrelated cleanup in the same commit; no tuning after seeing individual
   task outcomes unless it becomes a new hypothesis.
2. Rerun `python -m sacas lab histbench --format json`; compare macro P/R/F1
   **and total admitted-context tokens**, never F1 alone.
3. Acceptance is a Pareto judgement, not a strict conjunction:
   - **Prefer** Pareto improvements: higher/equal quality with fewer/equal tokens.
   - **Allow bounded trade-offs**: a regression in one dimension requires a
     clearly disproportionate gain in the other (e.g., +6.5% F1 for +3% tokens,
     or −0.002 F1 for −30% tokens).
   - **Final arbiter**: real coding-agent outcomes, once retrieval candidates
     survive this suite.
4. Weak-gold retrieval metrics are a proxy. Validate promising changes against
   real agent outcomes before treating them as progress.

## Harness failure policy

If infrastructure failure occurs (e.g., Windows `WinError 32` worktree locks),
**discard the entire affected run and rerun the same SHA/config**. Never record
an aggregate assembled from selectively re-run tasks across different passes.
